# Skill: stp2024 — Оформление отчетов по СТП 01-2024 в Typst

Данный скилл предназначен для автоматического создания и оформления учебных отчетов, лабораторных, курсовых и дипломных работ в системе **Typst** по стандарту **СТП 01-2024 БГУИР**.

---

## Пошаговый алгоритм выполнения

### 1. Проверка установки компилятора Typst
Перед началом работы убедиться, что компилятор Typst установлен в системе.
Выполнить команду:
```
typst --version
```
- Если Typst не установлен, сообщить пользователю о необходимости его установки.

---

### 2. Создание структуры папки проекта
Создать папку проекта с именем, указанным пользователем (например, `lab1` или `course_work`):

```
<имя_папки>/
├── media/        # Папка для изображений
├── title.typ     # Титульный лист
└── main.typ      # Главный файл документа (или разбитый на несколько .typ файлов)
```

> **Примечание по структуре файлов:** По запросу пользователя или для крупных работ разделы документа могут выноситься в отдельные `.typ` файлы и подключаться в `main.typ` с помощью директивы `#include "имя_файла.typ"`.

---

### 3. Определение типа работы и параметров шаблона

Выяснить у пользователя или определить из контекста тип работы:

1. **Лабораторная / Практическая работа**:
   - Отключить разрыв страницы перед заголовками 1 уровня:
     ```typst
     #show: stp2024.template.with(first_heading_new_page: false)
     ```
   - Содержание и список литературы обычно не требуются (если не запрошено отдельно).

2. **Курсовая работа / Дипломный проект**:
   - Использовать стандартный шаблон (заголовки 1 уровня с новой страницы):
     ```typst
     #show: stp2024.template
     ```
   - Обязательно включить полное содержание:
     ```typst
     #counter(page).update(4) // Установка номера страницы после титульного листа и задания
     #stp2024.full_outline()
     ```
   - Включить список использованных источников:
     ```typst
     #bibliography("bibliography.bib")
     ```

---

### 4. Проверка доступности шрифтов в системе

Выполнить команду для получения списка доступных шрифтов:
```
typst fonts
```

Убедиться, что в системе присутствуют обязательные шрифты:
- **`Times New Roman`** — основной шрифт текста (14pt, 1.15em)
- **`Courier New`** — шрифт листингов кода
- **`TeX Gyre Termes Math`** — основной математический шрифт ([скачать otf](https://mirrors.ctan.org/fonts/tex-gyre-math/opentype/texgyretermes-math.otf))
- **`XITS Math`** — для поддержки кириллицы в индексах формул
- **`GOST Type B`** — используется для основной надписи (рамки), при необходимости брать из папки `fonts/`

Если какой-либо шрифт отсутствует, выдать предупреждение пользователю.

### 5. Формирование текста отчета и академический стиль СТП БГУИР

Текст отчета может задаваться пользователем или формироваться по смыслу задания.

#### 5.1. Общие правила форматирования текста
При формировании/редактировании текста **ИСКЛЮЧИТЬ**:
- **Длинные тире (`—`)**: Запрещено использовать длинные тире `—`. Вместо них использовать только обычное среднее тире (`–`), отбиваемое пробелами с двух сторон;
- **Конструкции вида «не ..., а ...»**: Избегать противопоставлений со словами «не ..., а ...» (заменять на прямые утвердительные или нормативные формулировки);
- **Конструкции вида «Заголовок: Объяснение»**: Убрать построения предложений и абзацев формата `Термин: описание` или `Заголовок: текст`. Оформлять пояснения полноценными предложениями или пунктами списка;
- **Термины и пояснения в скобках**: Избегать конструкций вида `(некоторое пояснение)`, оформлять их нормальным текстом или списком;
- **Несправочные иностранные слова**, если у них есть русскоязычные аналоги в предметной области.

#### 5.2. Режим работы с текстом пользователя
- **Если пользователь предоставил свой текст и просит ЕГО НЕ РЕДАКТИРОВАТЬ**:
  - Исходный текст сохраняется в точности так, как передан пользователем;
  - В документ лишь добавляются необходимые заголовки (разделы/подразделы), структуры Typst и титульный лист;
  - Параллельно проводится **проверка стиля текста** на соответствие требованиям СТП (без внесения изменений в сам текст) и пользователю выводится отчёт о найденных отклонениях.

- **Если текст генерируется или пользователь просит его отредактировать**:
  Текст приводится в строгое соответствие с академическим стилем СТП БГУИР:
  - **Ясность и однозначность**: Четкость, логичность, отсутствие многозначности.
  - **Маркеры требований**: Обязательные требования излагать со словами: *«должен»*, *«следует»*, *«необходимо»*, *«требуется, чтобы»*, *«не допускается»*, *«запрещается»*. Другие положения излагать со словами: *«допускают»*, *«указывают»*, *«применяют»*.
  - **Математические выводы и описания процессов**: Запрещены личные местоимения (*«мы получили»*, *«мы нашли»*) и будущее/прошедшее время (*«получится»*, *«будем иметь»*). Используются безличные формы настоящего времени: *«получаем»*, *«определяем»*, *«находим»*, *«преобразуем к виду»*.
  - **Стиль заключения/вывода**: Итоги излагаются как констатация фактов в кратких страдательных причастиях: *«изучены»*, *«исследованы»*, *«разработана»*, *«предложена»*, *«испытана»*.
  - **Источники**: Запрещено дословное переписывание учебников без ссылок, а также запрещены ссылки на Википедию и незащищенные открытые ресурсы.

### 6. Оформление элементов документа (`lib/stp2024.typ`)

#### 6.1. Листинги кода
Листинги оформляются **БЕЗ указания языка подсветки** в блоке кода (просто ` ``` ` без `python`, `cpp` и т.д.):
```typst
#stp2024.listing[Наименование листинга][
  ```
  def main():
      print("Hello World")
  ```
] <lst_1>
```

#### 6.2. Использование `#include`
Если документ разбит на модули, подключать файлы через `#include`:
```typst
#include "01_titulnik.typ"
#include "06_vvedenie.typ"
```

#### 6.3. Пример структуры `main.typ`
```typst
#import "/lib/stp2024.typ"
#show: stp2024.template.with(first_heading_new_page: false)

#include "title.typ"

= Цель работы
...

= Ход выполнения работы
...

#stp2024.heading_unnumbered[Вывод]
...
```

### 7. Работа с медиафайлами (`media/`)

- Картинки добавляются только при необходимости.
- Если требуется вставить дефолтную/заглушечную картинку, скопировать файл `examples/no-image.png` в папку `media/`, переименовать его под нужное назначение (например, `media/butterfly.png`) и проинформировать пользователя.
- Оформление рисунков в Typst:
  ```typst
  #figure(
    caption: [Описание рисунка],
    image("media/filename.png", width: 80%)
  ) <fig1>
  ```
- Указать пользователю, какие медиафайлы были скопированы или требуют замены/добавления.

---

### 8. Правила оформления вывода и заключения

- **ВАЖНО**: Разделы «Введение», «Заключение», «Вывод», «Содержание» **НЕ являются заголовками 1 уровня** (не должны нумероваться).
- Для их оформления **ОБЯЗАТЕЛЬНО** использовать функцию:
  ```typst
  #stp2024.heading_unnumbered[Вывод]
  ```
  или
  ```typst
  #stp2024.heading_unnumbered[Заключение]
  ```

---

### 9. Компиляция и сборка проекта

После формирования структуры и содержимого выполнить сборку документа в PDF из корня проекта:
```
typst compile --root . <имя_папки>/main.typ
```
*(Параметр `--root .` используется для корректного импорта общего шаблона `lib/stp2024.typ` из корня проекта).*

Проверить отсутствие ошибок компиляции и уведомить пользователя о создании готового PDF-файла.
